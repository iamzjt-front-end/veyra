# Veyra community conduct

Veyra welcomes contributions and questions from people with different backgrounds and experience. These expectations apply to the project's issues, pull requests, reviews and other project-hosted spaces, including maintainer participation.

- Discuss code and behavior with evidence. Critique proposals without attacking people.
- Be respectful when disagreeing, make room for newcomers and accept corrections.
- Do not harass, threaten, discriminate, sexualize discussions or target people with insults.
- Do not publish another person's private information, credentials or correspondence without permission.
- Keep discussions relevant; avoid spam, repeated unwanted contact and retaliation against someone reporting a concern.

## Reporting and enforcement

For abuse or private safety concerns, use GitHub's **Report content / Report abuse to GitHub Support** controls or its reporting contact flow, as described in [Reporting abuse or spam](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam). GitHub handles those reports under its platform process. This project does not currently operate a separate private conduct-report inbox. Do not post personal details in a public issue to seek help.

Maintainers may edit or remove disruptive content, request a change in behavior, close/lock a thread or restrict participation using repository controls. Consider severity, context and repeated behavior; explain repository moderation decisions when doing so does not expose private information. A person involved in a dispute should not be the sole reviewer when another maintainer is available. New relevant context can be supplied in the affected thread when it is safe and open; GitHub platform actions can be raised with GitHub Support.

Report software vulnerabilities through [SECURITY.md](SECURITY.md). Neither disagreement about a technical decision nor a good-faith bug report is misconduct.
